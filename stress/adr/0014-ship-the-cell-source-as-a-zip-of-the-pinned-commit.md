# ADR-0014: Ship the cell source as a zip of the pinned commit

- Status: Accepted
- Date: 2026-11-20
- Amended by: ADR-0016
- Deciders: Dave Roberts (PSA)

## Context
Decision 7 has the cell script deploy runtime-isolation from a pinned commit. The control
plane fetches an application's scripts as a CodeBuild source: a git repository (with an
optional `sourceVersion`) or an S3 object. A run is built from a local commit that may not
be pushed, and the public repository's main branch may not hold the stress application at
all. The runtime-isolation sample also needs code generated by the Smithy CLI
(`src/smithy`, not committed), and the CodeBuild standard image has no Smithy CLI.

## Options considered
### Option 1: An S3 zip of the commit, with the generated code
`slice.sh deploy` runs `git archive` of the commit for `stress/application` and the
runtime-isolation sample, runs `smithy build` on that tree, zips it, and the slice's setup
stack uploads it as a CDK asset (`BucketDeployment`, `extract: false`). The application's
source is `S3`, `<bucket>/source/<hash>.zip`; the cell and tenant projects get read on the
bucket. Pros: the run deploys exactly what it was built from, pushed or not; the build
runs no Java; one object per commit. Cons: a cell is stamped with its source when it is
created, so a fixed script reaches only cells created after the next deploy.

### Option 2: The GitHub source at a commit SHA
Pros: no bucket. Cons: the commit must be pushed to the public repository first; the build
must install Java and the Smithy CLI, and fetch the code generators, on every cell build.

### Option 3: Generate the code in the build
Pros: the zip holds only committed files. Cons: adds a minute or two and two downloads to
every cell build, and makes Q-1's timing a measure of the tool install.

## Decision
Option 1, an S3 zip of the commit with the generated code. The run deploys exactly the
commit it was built from, pushed or not, and the cell build runs no Java. Options 2 and 3
both put the Smithy CLI install into every cell build, and Q-1 would time that install
instead of the cell.

## Consequences
The slice needs `git`, `zip` and the Smithy CLI on the runner's host. A fixed cell or tenant
script reaches an existing cell only after it is deleted and created again (the cell's
stamped source; control-plane ADR-0032). The zip is in the run folder, outside the
repository, and goes with `teardown --fixtures`.

Note 2026-11-20: ADR-0016 adds `samples/tenant-front-door/src/demo-cell/`
and `samples/tenant-front-door/src/shared/` to the archived paths, for the
stress cell's cell API origin.
