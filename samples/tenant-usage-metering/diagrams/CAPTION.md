Components: an emitter in a cell account, vendor-owned or tenant-owned, signs its usage events as its per-cell role and sends them to the ingest door; the ingest function admits an event only when the registry, written by the control plane's global hook on `PRE` and `POST` lifecycle events, places the tenant in the caller's cell and the meter catalog knows the meter; the ingest bus dedupes and retains the checked events and the raw store keeps them; the recounter recounts each hour from the raw store under the catalog's rules into usage records; the record outbox publishes each record to the usage bus, which subscriber accounts read through a `UsageSubscriber` that always has a dead-letter queue, and queues one delivery per sink; and the sink dispatcher sends each delivery to the billing system over HTTPS, authenticated with a secret or a SigV4 signature, or to the export bucket as JSON lines.

Architecture: an emitter calls the REST API's ingest route with SigV4 as its `<fleet>-ue-<cellId>` role; the ingest function checks each event against the DynamoDB table and publishes the accepted ones to the ingest bus, and writes the refused ones under `error/` in S3; on `BUS` the ingest bus delivers the checked events to subscriber accounts through an AWS RAM share, subscribe only; the bus delivers to Firehose, with an SQS dead-letter queue after retries, and Firehose writes `raw/` objects to S3; EventBridge Scheduler starts the Step Functions recounter, which reads an hour's objects and writes usage records to the table; DynamoDB Streams invoke the record publisher, which publishes `UsageRecorded` to the usage bus (shared with subscriber accounts through an AWS RAM share, subscribe only) and hands deliveries to the sink dispatcher, which sends to the billing system over HTTPS, with a secret it reads from Secrets Manager for a `SECRET` sink or signed with SigV4 as its own role for an `AWS_IAM` sink, or writes JSON lines to the export bucket; the control plane's CodeBuild global hook calls the REST API's admin routes, and the admin function writes the cell and tenant registrations into the table; and the share guard, a custom resource backed by a Lambda function, reads the registry before either share changes and fails the deploy if a listed account holds a cell that can still send.
